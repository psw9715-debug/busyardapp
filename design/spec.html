플랫폼
iOS 네이티브 → PWA로 전환. 보유 기기(아이폰 미니13 · 아이패드프로 1세대)로는 Xcode 실행 불가, 맥 없음. 무료 애플 ID라 사이드로드도 7일 만료라서 애초에 네이티브가 불리했음.
배포
GitHub Pages. 기존 GitHub 계정 사용. HTTPS 주소 필수(사파리 마이크 권한 조건) — 로컬 파일 열기 방식은 불가.
인쇄 트리거
수동 버튼. GPS 지오펜싱·WiFi SSID 감지 전부 불필요해짐 — 유료 개발자 계정 이슈, 백그라운드 감지 불안정성 리스크 소멸.
차량번호 규칙
4자리 중 첫째 자리는 항상 “1” 고정 (1000번대만 존재). 인식 보정에 직접 활용.
번호 없는 13칸
L열 하단, 로컬 번호 1–13. 현장 참고용 고정 번호일 뿐 순회 대상 아님 → 순회 시퀀스(1–109)에서 완전히 제외, 배치도엔 흐리게 표시만.
사용 자세
에어팟 낀 날은 음성 위주, 화면은 보조 확인용(안 보이는 날 대비 항상 크게). 순수 음성 전용으로 못박지 않고 화면·음성 둘 다 항상 동작.

1 기술 스택 & 배포

왜 PWA인가

Xcode는 macOS 전용이라 보유 기기(아이폰/아이패드)만으로는 네이티브 빌드 자체가 불가능. 아이패드 Swift Playgrounds는 그 기기에만 설치되고 아이폰으로 옮길 수 없음. 반면 PWA는 사파리로 한 번 열고 홈화면에 추가하면 끝 — 만료 없음, 맥 불필요, 아이콘·전체화면·오프라인까지 네이티브와 체감상 거의 동일.

구성

  • 순수 HTML/CSS/JS (프레임워크 없이 — 코드량 자체가 적어 빌드 도구가 오히려 손해)
  • manifest.json + Service Worker → 홈화면 아이콘, 오프라인 캐싱
  • 데이터 저장: localStorage / IndexedDB — 껐다 켜도 순회 데이터 유지
  • GitHub Pages 정적 호스팅, 수정 시 git push로 즉시 반영

2 데이터 모델 — 신차고지 109자리

차고지 프린트.xlsx의 신차고지-순서 시트와 spot_map.json을 대조 검증 완료 — 109/109 완전 일치, 누락·오타 0건.

필드설명
spot순회 순번 1–109. 이 순서가 실제 도보 동선.
cell엑셀 원본 좌표 (예: N3). 화면 그리드 위치로 환산하는 기준.
plate입력된 차량번호 뒤 3자리 (앞자리 “1”은 고정 가정, 화면엔 4자리 완전 표시).
statusempty · filled · vacant(공차)

그리드 좌표 변환

원본 병합 셀은 세로 3행(예: N3:N5)이 자리 하나. cell의 알파벳 열은 14열 그리드(A,B,C,D,E,F,G,H,I,J,K,L,M,N)로, 숫자 행은 (행-3)/3+1 공식으로 20행 그리드로 환산해 CSS Grid에 그대로 배치. 정비고·교통사업처·화단·CCTV·KEY·수소차고지·굴절버스 충전소·B2/B4/B5 라벨은 동일 그리드 위에 비입력 블록으로 함께 배치해야 실제 종이와 같은 모양이 나옴 (아래 3번 참고).

화면 구성 4요소

A
배치도 화면핀치줌 가능. 빈칸/입력완료(번호 표시)/공차(회색+“공차”) 구분. 진행 중 자리는 주황 하이라이트.

진행률 바하단 고정 “23/109 입력 완료”. 항상 화면에 보이는 위치.

4 음성 인식 규칙

⚠ 최우선 검증 필요

iOS 사파리의 webkitSpeechRecognition은 continuous:true를 사실상 무시하고 발화 한 번마다 자동 종료됨. 109자리 연속 인식을 위해선 종료될 때마다 즉시 재시작하는 체이닝이 필요하고, 재시작 지연·삑 소리가 현장 체감 속도를 좌우함. 서버 인식이라 차고지 전파 상태에 따라 아예 안 될 수도 있음. → 본 개발 착수 전, 독립된 1페이지 테스트 화면을 먼저 배포해 아이폰으로 직접 검증하고, 이 결과로 연속인식 vs 대형 키패드 우선 여부를 확정.

1000번대 고정 보정

모든 차량번호가 1로 시작하는 4자리라는 제약을 인식 파이프라인에 그대로 반영:

  • 숫자 시퀀스가 3자리로만 잡히면(042) 앞에 1을 자동으로 붙여 1042로 보정
  • 4자리인데 첫 자리가 1이 아니면(예: 잘못 인식된 7042) 오인식 가능성 높음 → 자동 확정하지 않고 화면에 큼직하게 띄워 1.5초 유예 후 확정(정정 명령으로 취소 가능)
  • 한글 숫자(“천사십이”, “일공사이” 등)든 아라비아 숫자든 동일 파이프라인으로 정규화

명령어 처리

발화동작
4자리 숫자 (한글/아라비아)현재 자리에 기입 → 다음 순번 자동 이동
“공차” / “빈칸” / “패스”현재 자리를 공차로 표시 → 다음 순번 이동 (동의어 처리)
“이전” / “정정”한 자리 뒤로 이동, 재입력 대기

구분 기준은 1.5초 무음 구간. AirPods 연결 시 Bluetooth HFP 오디오 세션으로 자동 전환.

5 인쇄

1
사무실 도착프린터 와이파이 연결은 평소처럼 수동으로.
2
앱 안 “인쇄” 버튼 탭오늘 데이터 1건 이상일 때만 활성화. GPS·SSID 자동 감지 없이 사용자가 직접 판단해 누름.
3
window.print() 호출iOS 표준 인쇄 시트(AirPrint) 자동 호출, 배치도 화면과 동일한 그리드 레이아웃으로 출력 CSS 별도 구성.

수동 버튼 방식이므로 NEHotspotNetwork/SSID 읽기 권한, Apple 유료 개발자 계정 승인, 백그라운드 위치 감지 정확도 — 인수인계 문서가 우려했던 리스크 전부 해당 없음.

6 MVP 이후 확장 대비 구조

  • 1일 2회차 — 순회 데이터에 round 필드만 추가하면 됨 (지금은 round:1 고정)
  • 구차고지 등 타 차고지 — spot_map.json 형태의 매핑 파일만 추가하면 동일 렌더링 로직 재사용. 지금 신차고지 매핑을 이 구조로 분리해두는 것이 핵심.
  • 히스토리 저장/조회 — 지금부터 매 순회를 날짜별 레코드로 저장해두면 나중에 조회 화면만 얹으면 됨

7 개발 순서

  • 0단계 — 음성인식 실측 검증. 최소 페이지 배포 → 아이폰 실기 테스트 (한글숫자 인식률 / 연속발화 재시작 지연 / 전파 약한 곳 동작 여부)
  • 1단계 — 배치도 정적 렌더링. xlsx 좌표 → 그리드 변환, 라벨·빈칸 포함 종이와 동일한 모양 확인
  • 2단계 — 수동 입력. 탭 → 키패드 입력, localStorage 저장, 진행률 표시
  • 3단계 — 음성 입력 연동. 0단계 검증 결과 반영해 연속인식 또는 확정 방식 구현, 1000번대 보정 로직
  • 4단계 — 인쇄. 인쇄 전용 CSS, 원본과 동일 레이아웃 검증
  • 5단계 — PWA 마감. manifest, 아이콘, Service Worker 오프라인 캐싱, GitHub Pages 배포 → 홈화면 추가 실기 확인
